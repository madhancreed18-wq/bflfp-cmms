NEW_GROUP_COLORS = ["FF0EA5E9", "FF14B8A6", "FFF97316", "FFA855F7", "FFEC4899",

def _free_group_color(c, fac):
    """The first palette colour no template and no group is using yet."""
    used = {(r["color"] or "").upper() for r in
            c.execute("SELECT color FROM pm_templates WHERE factory_id=?", (fac,))}
    used |= {(r["color"] or "").upper() for r in
             c.execute("SELECT color FROM pm_groups WHERE factory_id=?", (fac,))}
    for col in NEW_GROUP_COLORS:
        if col not in used:
            return col
    n = 1
    while f"FFUSER{n:02d}"[:8] in used:
        n += 1
    return f"FFUSER{n:02d}"[:8]

## Move job — who can take over a resigned employee's work

`static/index.html` `jobMoveDlg()` · `server/auth.py` bootstrap · `server/jobs.py` `update_job()`

The dialog always had two pickers, but they looked like one mixed list of names, so it
read as if operators were being offered as technicians. Both pickers now group their
names the same way — real people first, login accounts second — and a person with no
account attached is marked "ยังไม่มีโทรศัพท์ / no phone yet".

* **ผู้แจ้ง / ผู้ตรวจรับ (โอเปอเรเตอร์)** — operators only, plus the current reporter if a
  planner or admin raised the job. This is the field to change when the operator who
  reported the job has left: the reporter is the approver, both in the *Pending approval*
  tab and in the `signoff` guard.
* **ช่างหลัก (ช่างเท่านั้น)** — technicians only. It always was; it just did not look it.

`bootstrap` now sends `login_id` with `users` so the flag can be drawn for operators too,
and `update_job` refuses a reporter change to a name no login can reach — otherwise the
job would sit waiting for an approval nobody is able to give. Same shape as the existing
`_no_phone` guard on `lead_tech`.

Both lists only ever carry `active=1`, so switching someone off in **Manage → Users**
drops them out of the pickers by itself. Every move writes
`⇄ ผู้แจ้ง / reporter: X → Y (โดย …)` into the job's history.
