Project planning in the CMMS

A worked preview on one real-shaped project. Nothing in the app has changed — this is what it would look like.

1 · What a project needs that a job doesn't have

A PRJ job today is one row with one date. A project is a set of tasks with a start, a finish, a size, and a percentage done. Four things have to exist before any curve can be drawn:

  • A parent. One PRJ job is the project; its tasks are PRJ jobs pointing at it.
  • A date range per task, not a single planned date — a task that runs three weeks cannot be a dot on a calendar.
  • A weight per task. Planned man-hours is the honest one. Without it a two-hour task and a forty-hour task count the same, and the curve lies.
  • A recorded % complete, dated. This is the only part the app cannot work out for itself — somebody has to say where a task stands, and when they said it. Everything below falls out of those four.

6 · What it would take to build

Database — four columns on jobs, no new tables:

  • parent_id — which project this task belongs to
  • date_start, date_end — the task's own range (planned_date stays what it is; these are new)
  • weight_h — planned man-hours

progress already exists on jobs. A small job_progress(job_id, date, pct, by) table records who said what and when — that is the actual curve, and without it there is nothing to plot but today.

Screens — one new page under Planning: the header and tiles above, the timeline, the curve, the task table. Tasks are created and assigned through the machinery that already exists, so the crew's day and the technician's phone need no changes at all.

Reports — the curve and the timeline print to the same A4 the plan sheet uses, so a project review has a sheet.

Two decisions before I build it.
  • Weight by man-hours or by cost? Hours suit an in-house job; cost suits one with contractors and materials. Hours is the default above. Both is possible — two curves, one screen — but pick the one that gets updated.
  • Who updates % complete, and how often? A weekly figure from the project owner is enough for a curve that means something. Daily from technicians sounds better and is usually abandoned by week three.
What this reuses. Tasks are PRJ jobs, so they already have a crew, a machine, photos, a status flow, sign-off, and a place on the assign board and the technician's phone. The project page is a different view of work the app already tracks — not a second system to keep in step.
