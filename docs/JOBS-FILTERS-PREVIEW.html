All jobs — combining filters

Working preview on the 21 rows from your screenshot. Everything below is clickable — try stacking filters.

1 · What you have now

Three rows of chips — Show, Type, Status — and they already combine: picking Breakdown and Open gives you breakdowns that are open. Two things are missing:

  • One value per row. You cannot ask for Breakdown and CM together, or two technicians at once.
  • Only three columns can be filtered. Lead tech, Trade, Priority, Asset, Waiting on and the dates are on screen but not filterable — so "everything waiting on Kanya that is a breakdown" means scrolling.

2 · The proposal — try it

3 · How it works

  • The quick chips stay. They are the one-click answers to the questions a planner asks every morning, and they now hold more than one at a time.
  • + Filter adds any column. Pick the column, tick the values you want — each with its live count so you never pick an empty one. Columns with free text (Machine, Issue, Asset, Job ID) get a search box instead.
  • Everything ANDs by default, values inside one filter OR together: Type is BD or CM, and Lead tech is Kanya. That is what people mean without having to be told.
  • Active filters are visible as pills with an × on each — so the count on screen always has a visible reason. Today, a filter left on three chips away is invisible.
  • Save this view names the whole set and remembers it. "My breakdowns to accept" becomes one click tomorrow.
A bug worth fixing at the same time. Export Excel only sends the Type and Status chips and the search box to the server — it ignores the Show chip and the From / To dates. So filtering to Overdue and exporting gives you the whole list, quietly. Whatever we build, Export has to send exactly what is on screen.

4 · What I would not build

A full query builder — field / operator / value rows with AND, OR and brackets — is the other way to read "dynamic filter". It is more powerful, and I would skip it:

  • Every common question a planner has is a plain AND of a few columns. The builder makes that case slower, not faster.
  • It needs teaching. The chips and tick-lists above need none.
  • It is roughly three times the work, and most of it goes unused.

If a rare question needs OR across different columns, the honest answer is Export Excel and a pivot — not a query language inside a maintenance app.

Scope. All of this is client-side over the list the page has already fetched, so it is fast and needs no server change — except Export, which is built server-side and needs the filter set passed to it. One caution: the filters only see what was loaded, which is the From / To range at the top. Widen the range first, then filter.
